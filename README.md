# runegear-live

RuneGear 게임이 시작할 때 읽는 원격 설정 파일을 두는 공개 저장소다.
게임 코드는 비공개 저장소에 있고, 앱이 로그인 없이 읽어야 하는 파일 하나만 여기에 둔다.

이 저장소에는 서버 프로그램이 없다.
`main` 브랜치의 `config.json`을 GitHub가 정적 파일로 내주고, 앱은 아래 주소를 읽는다.

```
https://raw.githubusercontent.com/DDEOK/runegear-live/main/config.json
```

> [!warning] `main`에 푸시하면 곧바로 모든 플레이어에게 나간다
> 올리기 전에 `python3 tools/validate.py`를 돌린다.
> 푸시하면 GitHub Actions가 같은 검사를 다시 돌리지만, 검사가 실패해도 파일은 이미 나가 있다.
> 큰 변경은 브랜치에서 고치고 검사가 통과한 뒤 `main`에 합친다.

## 무엇을 정하나

| 칸 | 하는 일 |
|---|---|
| `android`·`ios`의 `minVersion` | 이보다 낮은 앱은 강제 업데이트 창에서 멈추고 스토어로 보낸다 |
| `android`·`ios`의 `latestVersion` | 이보다 낮은 앱에는 「새 버전이 나왔어요」 창(나중에·업데이트)을 띄운다 |
| `android`·`ios`의 `storeUrl` | 업데이트 버튼이 여는 스토어 주소 |
| `notices` | 시작할 때 차례로 띄우는 공지 창 |
| `events` | 공지 다음에 차례로 띄우는 이벤트 창 |

## 앱이 이 파일을 쓰는 순서

1. 앱이 켜지면 기기 저장을 먼저 읽는다.
2. 이 파일을 3초 안에 받는다. 받지 못하면 마지막으로 받은 사본(기기 캐시)을 쓰고, 사본도 없으면 이 단계를 건너뛴다.
3. 버전을 비교한다. 강제 업데이트면 여기서 멈추고, 그 밖에는 계속 간다.
4. 공지를 JSON 순서대로 띄우고, 그 뒤 이벤트를 JSON 순서대로 띄운다. 창을 닫으면 다음 창이 뜬다.
5. 클라우드 저장 로그인·합치기, 끊긴 출전 보상 복구를 거쳐 로비로 들어간다.

인터넷이 없어도 게임은 켜진다.
진행을 막는 것은 강제 업데이트 하나뿐이다.

## 파일 형식

```json
{
  "schema": 1,
  "android": {
    "minVersion": "0.41.0",
    "latestVersion": "0.42.0",
    "storeUrl": "https://play.google.com/store/apps/details?id=com.ddeok.runegear"
  },
  "ios": {
    "minVersion": "0.41.0",
    "latestVersion": "0.42.0",
    "storeUrl": "https://apps.apple.com/app/id6824164217"
  },
  "notices": [
    {
      "id": "notice.2026-11-maintenance",
      "start": "2026-11-01T00:00:00+09:00",
      "end": "2026-11-08T00:00:00+09:00",
      "title": { "ko": "원정대 소식", "en": "Expedition News" },
      "body": { "ko": "본문", "en": "Body" },
      "hide": "forever"
    }
  ],
  "events": [
    {
      "id": "event.2026-11-week1",
      "start": "2026-11-01T00:00:00+09:00",
      "end": "2026-11-08T00:00:00+09:00",
      "title": { "ko": "이벤트 제목", "en": "Event Title" },
      "body": { "ko": "본문", "en": "Body" },
      "image": "",
      "open": "shop",
      "hide": "today"
    }
  ]
}
```

### 버전 칸

- 형식은 `MAJOR.MINOR.PATCH`이고, 빌드 번호까지 가르려면 `0.41.0+62`처럼 `+빌드`를 붙인다.
- `v` 접두사나 `-beta` 같은 꼬리는 쓰지 않는다. 형식이 틀리면 앱은 그 값을 무시하고 막지 않는다.
- 내 버전이 `minVersion`보다 낮으면 강제, 그렇지 않고 `latestVersion`보다 낮으면 선택 업데이트다.
- `minVersion`을 `latestVersion`보다 크게 적으면 앱은 `latestVersion`을 `minVersion`으로 끌어올려 읽는다.
- `storeUrl`은 `https://`, `market://`, `itms-apps://`로 시작해야 한다. 비면 앱이 자기 스토어 주소를 만든다.
- 버전 칸의 모양은 앞으로 `schema`가 바뀌어도 그대로 둔다. 옛 앱도 강제 업데이트를 읽어야 하기 때문이다.

### 공지·이벤트 칸

| 칸 | 필수 | 설명 |
|---|---|---|
| `id` | 예 | 소문자·숫자·`.`·`-`·`_` 1~40자. 공지와 이벤트를 통틀어 겹치면 안 된다 |
| `title` | 예 | `ko`·`en` 중 하나는 있어야 한다. 40자 이하 |
| `body` | 아니요 | `ko`·`en`. 600자 이하. 줄바꿈은 `\n` |
| `start`·`end` | 아니요 | ISO 8601 날짜와 시간대(`Z`나 `+09:00`). 비면 기한 없음. `start`는 포함, `end`는 포함하지 않는다 |
| `hide` | 아니요 | 아래 표. 기본은 `today` |
| `open` | 아니요 | 「바로 가기」 버튼이 여는 게임 안 화면. 비면 닫기 버튼만 있다 |
| `image` | 아니요 | 게임 아틀라스에 있는 그림 ID. 없는 ID면 그림 없이 보인다 |

`hide` 값:

| 값 | 창 아래에 보이는 것 | 숨김 |
|---|---|---|
| `none` | 닫기만 | 다음 시작에도 또 뜬다 |
| `today` | 「오늘 보지 않기」 | 기기 날짜로 오늘 하루 |
| `forever` | 「다시 보지 않기」 | 그 `id`는 다시 뜨지 않는다 |

`open` 값: `shop`(상점), `codex`(도감), `research`(강화), `history`(기록), `character`(캐릭터), `stage`(스테이지 고르기), `settings`(설정).

한쪽 언어가 비어 있으면 다른 언어 글로 보인다.
글은 서식 태그를 해석하지 않고 그대로 보인다.

## 「다시 보지 않기」는 어디에 저장되나

이 파일에는 공지 내용만 있고, 누가 무엇을 봤는지는 없다.
「오늘 보지 않기」·「다시 보지 않기」는 공지 `id`별로 플레이어 기기의 게임 저장에 남는다.
게임 저장은 클라우드 저장(Play 게임즈·Game Center)으로 합쳐지므로, 다른 기기나 다시 설치한 앱에서도 숨긴 공지는 다시 뜨지 않는다.

그래서 `id`를 바꾸면 새 공지로 본다.
이미 「다시 보지 않기」를 누른 사람에게도 다시 보여야 하는 고침이면 `id`를 바꾸고, 오타 고침처럼 다시 띄울 필요가 없으면 `id`를 그대로 둔다.
숨김 기록은 1년이 지나면 지워지므로, 1년 넘게 이어지는 공지는 그때 다시 한 번 보인다.

## 고치는 법

1. `config.json`을 고친다.
2. `python3 tools/validate.py`로 검사한다. 「통과」가 나와야 한다.
3. 커밋하고 `main`에 푸시한다.
4. 반영까지 몇 분 걸린다. GitHub의 raw 주소가 약 5분 동안 사본을 내주기 때문이다.

자주 하는 일:

| 하려는 것 | 고칠 곳 |
|---|---|
| 새 버전을 냈고 업데이트를 권하고 싶다 | 두 플랫폼의 `latestVersion` |
| 옛 버전을 막아야 한다(저장 형식 변경, 심각한 버그) | 두 플랫폼의 `minVersion`. 스토어에 새 버전이 실제로 나온 뒤에 올린다 |
| 공지를 띄운다 | `notices`에 항목 하나 |
| 공지를 내린다 | 그 항목을 지우거나 `end`를 지난 시각으로 |
| 이벤트 창에서 상점으로 보내고 싶다 | 이벤트 항목의 `open`을 `shop`으로 |

> [!caution] `minVersion`을 잘못 올리면 오프라인 플레이어가 갇힌다
> 앱은 마지막으로 받은 사본의 강제 업데이트도 지킨다.
> 스토어 심사가 끝나기 전에 `minVersion`을 올리면 업데이트할 수 없는 상태로 막힌다.
> 잘못 올렸으면 곧바로 되돌려 푸시한다. 인터넷에 연결된 기기는 다음 시작 때 풀린다.

## 검사

`tools/validate.py`는 게임 안 읽기 코드(`RemoteConfig.TryParse`)와 같은 기준으로 본다.
게임은 잘못된 항목 하나만 버리고 나머지를 보이지만, 이 검사는 버려질 항목이 하나라도 있으면 실패로 알린다.
조용히 빠지는 공지를 올리기 전에 잡기 위해서다.

상한값(파일 64KB, 목록마다 10개, 제목 40자, 본문 600자)은 지금 게임의 값이다.
게임의 상한을 바꾸면 이 스크립트도 같이 고친다.

## 개발 중 확인

게임 개발 빌드에는 이 파일 없이 모든 경우(강제·선택 업데이트, 공지·이벤트 여러 개, 받기 실패, 캐시 사용)를 만드는 개발 명령이 있다.
명령 목록은 게임 저장소의 사용법 문서에 있다.
